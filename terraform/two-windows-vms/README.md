# Windows VM POC: web + SQL disk layout (Terraform)

Deploys the Windows Server 2025 VMs listed in [terraform.tfvars](terraform.tfvars). Each VM's OS disk, data disks, drive letters and volume labels are configured there. A one-time in-guest script formats the disks and assigns their letters.

**What it demonstrates:** a local child module called with `for_each`; typed `optional()` defaults and validation owned by the module; zonal Premium SSD v2; managed Run Command; and Microsoft's SQL-on-VM disk guidance.

## Structure

| Path | Holds |
|---|---|
| `main.tf` | Shared resources (resource group, VNet, subnet, NSG, admin password) and the `module "vm"` call, one instance per entry in `vms` |
| `modules/windows-vm/` | Everything for one VM: public IP, NIC, VM, data disks and attachments, disk setup Run Command, auto-shutdown. Owns the data disk defaults and validation. |
| `modules/windows-vm/scripts/Initialize-DataDisks.ps1` | One-time in-guest disk setup, run by the module |
| `scripts/Get-DriveInventory.ps1` | Read-only drive snapshot you run yourself (see below) |

## Layout

| VM | Size | Drives |
|---|---|---|
| web1 | `Standard_B2als_v2` | C: OS (128 GB StandardSSD), D: Data |
| db01 | `Standard_B4als_v2` | C: OS (128 GB Premium), D: Application, E: SQLTemp, F: SqlData, G: SqlLogs, H: SqlBackups |

CD/DVD drives move to Z:. Both VMs are in zone 1.

## Design decisions

| Decision | Reason |
|---|---|
| No temp-disk VM sizes; tempdb on a managed disk (E:) | The temp disk is wiped on deallocation, so tempdb there needs startup automation, which would compete with hardening scripts. A managed disk persists, so a one-time setup is enough. This is Microsoft's documented alternative to tempdb on the temp disk. |
| Pagefile stays on C: | Azure's default for sizes without a temp disk. A SQL Server with *max server memory* set pages very little. |
| db01 is `B4als_v2` (4 vCPU) | It needs 5 data disks. 2-vCPU sizes allow at most 4. `B4pls_v2` is cheaper but Arm64, which can't run the x64 image. |
| Zone 1 | Premium SSD v2 attaches only to zonal VMs in East US 2. A zonal VM's disks must be in the same zone. |
| Caching: SQLTemp ReadOnly; SqlData, SqlLogs, others None | Microsoft guidance: logs None, tempdb on a data disk ReadOnly. Premium SSD v2 doesn't support host caching. |
| 64 KB NTFS allocation units on SQL volumes | Microsoft guidance for SQL data, log and tempdb files on data disks |
| Premium SSD v2 `iops` / `mbps` inputs | Performance is set separately from size. Validation applies Azure's rules: IOPS from 3,000 up to 500 per GiB (max 80,000); MB/s from 125 up to 0.25 per IOPS (max 2,000), fixed at 125 for disks of 6 GiB or less. Also check the VM's own uncached limit (`B4als_v2`: 6,400 IOPS / 145 MB/s for all data disks combined; check with `az vm list-skus --size <size>` and look for `UncachedDisk*`), because disk performance above that is wasted. |
| Explicit `lun` per disk in tfvars | A disk's LUN is part of its identity. If list position decided it, inserting a disk would renumber (detach and reattach) every disk after it. |
| One-time Run Command, LUN-based | Runs at deploy only, never at boot. The LUN is the identifier Azure and Windows share. SCSI sizes only: NVMe (v6) sizes number disks differently. |

## Run

```powershell
az login
$env:ARM_SUBSCRIPTION_ID = az account show --query id --output tsv
$env:TF_VAR_allowed_rdp_source_ip = Invoke-RestMethod https://api.ipify.org

terraform init
terraform plan -out tfplan
terraform apply tfplan
```

Connect:

```powershell
terraform output rdp_commands
terraform output -raw admin_password | Set-Clipboard
```

Check the disk setup output without RDP:

```powershell
az vm run-command show --resource-group rg-lab-eastus2 --vm-name db01 --name initialize-data-disks --instance-view --query instanceView.output --output tsv
```

Snapshot disks, volumes, letter reservations and pagefile (read-only):

```powershell
az vm run-command invoke --resource-group rg-lab-eastus2 --name db01 --command-id RunPowerShellScript --scripts '@scripts\Get-DriveInventory.ps1'
```

Tear down (stops all charges):

```powershell
terraform destroy
```

## Adding or changing VMs

Edit `terraform.tfvars`. Leave out `caching` and `allocation_unit_kb` when they match the module defaults (`None`, 4 KB). Each data disk sets its `lun` explicitly (0–63, unique per VM). The convention is sequential in drive-letter order. Because LUNs are explicit, list order doesn't matter, and adding a disk never renumbers the others. Changing an *existing* disk's LUN detaches and reattaches it, so treat LUNs as fixed once deployed.

## Notes

- **Cost:** about $0.05/hour for web1 and $0.15/hour for db01 (compute plus Windows license), plus roughly $30/month for disks. Auto-shutdown at 19:00 Central deallocates the VMs, but disks and public IPs still bill. Use `destroy` when you're done.
- The admin password is generated by Terraform and stored in local state, which is gitignored.
- If your IP changes, set `TF_VAR_allowed_rdp_source_ip` again and re-apply.
