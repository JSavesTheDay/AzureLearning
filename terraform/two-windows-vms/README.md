# Windows VM POC: web + SQL disk layout (Terraform)

Deploys the Windows Server 2025 VMs listed in [terraform.tfvars](terraform.tfvars). Each VM's OS disk, data disks, drive letters and volume labels are configured there. A one-time in-guest script formats the disks and assigns their letters.

**What it demonstrates:** a typed `map(object)` variable with `optional()` defaults and validation; flattening nested collections for `for_each`; zonal Premium SSD v2; managed Run Command; and Microsoft's SQL-on-VM disk guidance.

## Layout

| VM | Size | Drives |
|---|---|---|
| web1 | `Standard_B2als_v2` | C: OS (128 GB StandardSSD), D: Data |
| db01 | `Standard_B4als_v2` | C: OS (128 GB Premium), D: Application, E: SQLTemp, F: SqlData, G: SqlLogs, H: SqlBackups |

CD/DVD drives move to Z:. Both VMs are in zone 1.

## Design decisions

| Decision | Reason |
|---|---|
| No temp-disk VM sizes; tempdb on a managed disk (E:) | The temp disk is wiped on deallocation, so tempdb there needs startup automation, which would compete with hardening scripts. A managed disk persists, so a one-time setup is enough. This is Microsoft's documented alternative to tempdb on the temp disk. |
| Pagefile stays on C: | Azure's default for sizes without a temp disk. A SQL Server with *max server memory* set pages very little. |
| db01 is `B4als_v2` (4 vCPU) | It needs 5 data disks. 2-vCPU sizes allow at most 4. `B4pls_v2` is cheaper but Arm64, which can't run the x64 image. |
| Zone 1 | Premium SSD v2 attaches only to zonal VMs in East US 2. A zonal VM's disks must be in the same zone. |
| Caching: SQLTemp ReadOnly; SqlData, SqlLogs, others None | Microsoft guidance: logs None, tempdb on a data disk ReadOnly. Premium SSD v2 doesn't support host caching. |
| 64 KB NTFS allocation units on SQL volumes | Microsoft guidance for SQL data, log and tempdb files on data disks |
| One-time Run Command, LUN-based | Runs at deploy only, never at boot. The LUN is the identifier Azure and Windows share. SCSI sizes only: NVMe (v6) sizes number disks differently. |

## Run

```powershell
az login
$env:ARM_SUBSCRIPTION_ID = az account show --query id --output tsv
$env:TF_VAR_allowed_rdp_source_ip = Invoke-RestMethod https://api.ipify.org

terraform init
terraform plan -out tfplan
terraform apply tfplan
```

Connect:

```powershell
terraform output rdp_commands
terraform output -raw admin_password | Set-Clipboard
```

Check the disk setup output without RDP:

```powershell
az vm run-command show --resource-group rg-lab-eastus2 --vm-name db01 --name initialize-data-disks --instance-view --query instanceView.output --output tsv
```

Tear down (stops all charges):

```powershell
terraform destroy
```

## Adding or changing VMs

Edit `terraform.tfvars`. Data disks attach in list order (index = LUN), so **append** new disks to the end of a list. Inserting a disk in the middle shifts the LUNs of the disks after it, and Terraform would then detach and reattach them.
